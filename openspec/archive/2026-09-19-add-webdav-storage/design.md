# Design: add-webdav-storage

## Context
Источник аудиофайлов — переменная величина: локальная ФС (уже есть), WebDAV сейчас, Google Drive/S3/WebDAV-серверы позже. Плеер и библиотека не должны зависеть от провайдера. Яндекс.Диск даёт WebDAV «из коробки», что позволяет стартовать без OAuth-верификаций.

## Goals / Non-Goals
- Goals: единый контракт провайдера, рабочая реализация WebDAV (Яндекс.Диск), офлайн-кэш, расширяемость.
- Non-Goals: двухсторонняя синхронизация, запись на сервер, OAuth-поток Яндекса, публикация в Play.

## Decisions

### Контракт StorageProvider
Все операции асинхронные:
- `authenticate()` / `isAuthenticated` / `signOut()`
- `listEntries(parentRef)` → папки и файлы (`RemoteEntry`)
- `getMetadata(ref)`
- `openStream(ref)` → поток байт для потокового воспроизведения (с поддержкой Range)
- `download(ref, targetPath, onProgress)` → локальный файл

Идентификация — непрозрачный `sourceRef` (для WebDAV — путь), чтобы плеер не зависел от специфики. `RemoteEntry`: `ref`, `name`, `isFolder`, `size`, `modifiedAt`, `mimeType`.

### Яндекс.Диск: параметры подключения
- Endpoint: `https://webdav.yandex.ru` (реализация принимает произвольный URL — для Nextcloud/self-hosted).
- Авторизация: Basic (логин + **пароль приложения**; в Яндекс.Диске пароль приложения выдаётся в настройках Яндекс ID и работает при включённой двухфакторной аутентификации).
- Листинг: `PROPFIND` с `Depth: 1`, обработка `207 Multi-Status`.
- Скачивание/стриминг: `GET` с поддержкой `Range` (для докачки и seek).
- Ограничения: rate limiting Яндекса — кэшируем листинги, не дёргаем листинг на каждый чих.

### Пакет
`webdav_client` (уже заложен в стеке проекта). Если его возможностей не хватит (кастомные заголовки/поток), падаем на `http`/`dio` + свой разбор XML — но начинаем с пакета.

### Импорт удалённой книги
Переиспользуем `ImportBookFromFolder`: для WebDAV делаем `WebDavAudioSource implements AudioSource`:
- `listAudioFiles(folderRef)` → `LIST`/`PROPFIND`, фильтр по расширениям, естественная сортировка — как локально;
- `probeDuration` / `readMetadata` — через Android `MediaMetadataRetriever.setDataSource(url, headers)` (поддерживает HTTP(S) с заголовками), без полного скачивания; если не удалось — нулевая длительность (уточняется при воспроизведении).
Треки по-прежнему скрыты от пользователя.

### Хранение и схема
- `Book`: `sourceProvider` = `'webdav'`, `sourceRef` = путь папки на сервере.
- `Track`: `sourceProvider`, `sourceRef` = путь к файлу, `cachePath` (nullable) = локальная копия; `uri` хранит актуальный путь/URL для плеера. Требуется миграция drift (schema+1).

### Воспроизведение и кэш
Приоритет источника: **локальный кэш → поток из провайдера**.
- Стриминг: `just_audio` с `AudioSource.uri(..., headers: {'Authorization': ...})` (just_audio поднимает локальный прокси для заголовков); seek через Range.
- Кэш: файлы в каталоге приложения, индекс в drift по `(bookId, trackId)`; статусы: «нет», «скачивается», «готово».
- Автоочистка: лимит размера, вытеснение по времени последнего прослушивания. Ручная очистка по книге и полностью.
- Докачка по `Range`, где поддерживается.

### Безопасность
Пароль приложения хранится в `flutter_secure_storage` (Android Keystore), не в SharedPreferences и не в логах. URL и логин можно хранить в обычных настройках.

### Расширяемость
S3 (`minio`), WebDAV-серверы (Nextcloud) и Google Drive (`add-storage-providers`) реализуют тот же интерфейс. Регистрация провайдера — запись в реестре; UI хранилищ строится по реестру.

## Risks
- Яндекс может требовать пароль приложения/2FA — UX-подсказки обязательны.
- Rate limits и троттлинг на листинг/скачивание — кэшируем листинги, ограничиваем параллелизм.
- `MediaMetadataRetriever` по сети может быть медленным/нестабильным — предусмотрен fallback на нулевую длительность и уточнение при воспроизведении.
- Локальный прокси just_audio для заголовков добавляет накладные расходы — для тяжёлых книг кэш предпочтительнее.
- Разные WebDAV-серверы отличаются ответами (кодировки имён, `207`, глубины) — покрываем тестами на фикстурах.
