# Design: add-unified-playback

## Context
Книга состоит из N аудиофайлов, но пользователю нужен один непрерывный поток с одной шкалой. Нужно совместить требование «скрыть файлы» с реальностью файлового воспроизведения и фоновым сервисом Android.

## Goals / Non-Goals
- Goals: единый таймлайн, gapless, перемотка через границы файлов, фоновое воспроизведение.
- Non-Goals: изменение состава треков во время воспроизведения, потоковая загрузка (см. `storage-providers`).

## Decisions

### Единая очередь через ConcatenatingAudioSource
Используем очередь `just_audio` из треков книги, отсортированных в `book-library`. Суммарная позиция = сумма длительностей треков до текущего + позиция внутри текущего.

Альтернатива — играть по одному файлу вручную. Отклонено: теряется gapless и усложняется фоновый сервис.

### Модель позиции
Позиция хранится как `(trackIndex, offsetMs)` — это устойчивое представление, не зависящее от суммарной длительности. Суммарная позиция вычисляется на лету для UI и seek.

### Обработка неточных длительностей
Длительности из метаданных могут отличаться от реальных (VBR). Суммарный таймлайн строится по данным, полученным при сканировании; при воспроизведении текущая суммарная позиция уточняется через позицию реального трека. Допускается небольшая погрешность шкалы; seek выполняется по (trackIndex, offsetMs) для точности.

### Фоновое воспроизведение
`just_audio_background` даёт media notification, управление с lock screen и foreground service. Android 14 требует объявленный foreground service type `mediaPlayback` и разрешение `POST_NOTIFICATIONS`.

## Risks
- Разные контейнеры/кодеки могут давать паузу на стыке — gapless не гарантирован для всех форматов.
- Длинные книги (сотни файлов) — нагрузка на очередь; проверяем на больших наборах.
