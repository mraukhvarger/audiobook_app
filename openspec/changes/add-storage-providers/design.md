# Design: add-storage-providers

## Context
Источник аудиофайлов — переменная величина: локальная ФС, Google Drive сегодня, S3/WebDAV/свой сервер завтра. Плеер и библиотека не должны знать, откуда приходят байты.

## Goals / Non-Goals
- Goals: единый контракт провайдера, рабочая реализация Google Drive, офлайн-кэш, расширяемость.
- Non-Goals: синхронизация позиций между устройствами (это фаза 4, `server`), стриминг с адаптивным битрейтом.

## Decisions

### Контракт StorageProvider
Единый интерфейс, все операции асинхронные:
- `authenticate()` / `isAuthenticated` / `signOut()`
- `listEntries(parentRef)` → папки и файлы
- `getMetadata(ref)`
- `openStream(ref)` → поток байт для потокового воспроизведения
- `download(ref, targetPath, onProgress)` → локальный файл

Идентификация объекта — непрозрачный `sourceRef` (для Drive — fileId), чтобы плеер не зависел от специфики провайдера.

### Google Drive: бесплатно для себя
Google Drive API бесплатен. Для личного использования достаточно проекта в Google Cloud Console с экраном согласия OAuth в режиме **Testing** и своим Google-аккаунтом в списке тестовых пользователей (до 100). Scope `drive.readonly` относится к ограниченным, но верификация нужна только для публикации приложения в Play и для чужих пользователей; для себя — не требуется. Ограничения: refresh-токен в Testing-режиме может истекать через ~7 дней — периодически нужна повторная авторизация. Это приемлемо для MVP, но заложим в UI понятную повторную авторизацию.

### Источники воспроизведения
Приоритет источника для трека:
1. Локальный кэш (если файл скачан).
2. Потоковое чтение из провайдера (если поддерживается и есть сеть).
3. Скачивание по требованию с индикатором.

`just_audio` умеет играть `AudioSource.uri` с локальным путём и с URL; для Drive стриминг используем через медиа-URL/Download API.

### Офлайн-кэш
Кэш — обычные файлы в каталоге приложения, индексируются в drift по `(bookId, trackId)`. Скачивание возобновляемое (докачка по диапазону, где поддерживается). Автоочистка по лимиту размера с вытеснением по времени последнего прослушивания.

### Расширяемость
S3 (`minio`), WebDAV (`webdav_client`), Яндекс.Диск (REST/WebDAV) и собственный сервер (фаза 4) реализуют тот же интерфейс. Регистрация провайдера — запись в реестре; UI хранилищ строится по реестру.

## Risks
- Refresh-токен Google в Testing-режиме истекает — нужна мягкая повторная авторизация.
- Потоковое воспроизведение может буферизоваться на плохой сети — кэш/скачивание решает.
- Лимиты Google API на количество запросов — кэшируем листинги.
