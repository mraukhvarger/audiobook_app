# Design: add-volume-controls

## Context
just_audio даёт `setVolume(0.0–1.0)`, но значение выше 1.0 платформа не принимает — цифровое усиление сверх полной шкалы невозможно обычной громкостью. Штатная системная громкость Android квантована ~15 ступенями. Значит нужны два независимых слоя: программная громкость плеера (мелкий шаг, ослабление) и платформенное усиление (для тихих записей).

## Goals / Non-Goals
- Goals: плавная регулировка с шагом мельче системного; усиление тихих книг; защита от искажений; сохранение настроек.
- Non-Goals: автоматическая нормализация по анализу всей книги (отдельный change); эквалайзер; изменение системной громкости вместо пользователя.

## Decisions

### Два слоя громкости
1. **Программная громкость плеера** (`just_audio` `setVolume`, 0.0–1.0) — отвечает за основной диапазон и плавность. Пользователь двигает мелкошаговый слайдер (шаг 1% или 0.5 дБ), значение мапится в `setVolume`.
2. **Усиление** (boost) — отдельный регулятор поверх, для тихих записей.

Системная громкость остаётся как есть (аппаратные кнопки продолжают работать как грубая регулировка). Плеер не управляет системной шкалой.

### Плавность
Диапазон слайдера — например 0–100% с шагом 1%, либо dB-шкала от −60 дБ до 0 дБ. Смена значения применяется к `setVolume` небольшими рампами (интерполяция за ~100–200 мс), чтобы не было «зиппер-шума» и щелчков. Значение по умолчанию: 100% программной громкости.

### Усиление (boost) через Android LoudnessEnhancer
Для boost используем `just_audio` `AudioPipeline` с `AndroidLoudnessEnhancer`, привязанным к `androidAudioSessionId`:
- диапазон усиления: 0…+20 дБ (шаг, например, +1 дБ);
- значение задаётся в миллибелах (`setTargetGain`), 0 = выключено;
- эффект переживает gapless-переходы в рамках сессии, но при смене аудио-сессии должен переприменяться.

LoudnessEnhancer только **усиливает**, не ослабляет; ослабление делает программная громкость.

### Защита от клиппинга
Усиление тихой записи безопасно, но на громком материале boost даёт перегрузку. Варианты (выбрать при реализации):
- **Limiter** (`DynamicsProcessing` с лимитером, API 28+) после LoudnessEnhancer; при недоступности — программная оценка и предупреждение.
- Мягкое ограничение диапазона boost + визуальная индикация «Boost» и предупреждение о возможных искажениях.
- Значение boost ограничено сверху (жёсткий cap) независимо от слайдера.

### Модель настроек
- Глобальные значения: `volume` (0.0–1.0), `boostDb` (0…+20).
- Опционально per-book override: усиление для конкретной книги (хранится в drift, как `book_progress`); громкость — глобальная.
- Хранение: SharedPreferences для глобальных; drift — если включим per-book.

### Взаимодействие с системой
- Аппаратные кнопки громкости продолжают менять системную громкость (не перехватываем).
- Итоговая громкость = системная × программная + boost. При системном максимуме пользователь получает полный диапазон приложения.

### Расширяемость
Абстракция `VolumeController` в domain: программная громкость + boost. Android-реализация поверх just_audio `setVolume` + `AndroidLoudnessEnhancer`. iOS — отдельная реализация (например, через AVAudioEngine/`AVAudioMix` или `AVPlayer.volume`), без LoudnessEnhancer.

## Risks
- Перегрузка и искажения при boost на громком материале — нужен лимитер/предупреждение.
- `AndroidLoudnessEnhancer` привязан к аудио-сессии; при смене трека/сессии эффект может сбрасываться — потребуется переприменение.
- Лимит +20 дБ: очень тихие записи всё равно могут остаться тихими — это граница платформы.
- iOS не поддерживает LoudnessEnhancer — нужен отдельный путь (вне текущего change).
- Плавность зависит от того, как платформа применяет `setVolume`; при кликах используем собственную рампу.
