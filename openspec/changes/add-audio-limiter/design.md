# Design: add-audio-limiter

## Context
`just_audio` из платформенных эффектов Android умеет только `LoudnessEnhancer` и `Equalizer` (см. его `AudioPlayer.java`), лимитера/компрессора там нет. Значит нужен свой способ прикрепить эффект к аудио-сессии.

## Goals / Non-Goals
- Goals: убрать клиппинг при boost, мягкое ограничение, включатель/настройки, деградация без падения.
- Non-Goals: лимитер как «улучшатель» звука, многополосная обработка по умолчанию, анализ громкости.

## Decisions

### Эффект: Android `DynamicsProcessing`
Используем `android.media.audiofx.DynamicsProcessing` (API 28+):
- стадия **LIMITER** с потолком −1 дБFS и мягкой атакой/восстановлением;
- опционально позже — мягкий компрессор (MBC) с большим порогом и «мягким коленом» как дополнительный этап, но в этом change достаточно лимитера.

Альтернативы:
- `LoudnessEnhancer` — это гейн, не лимитер, не подходит.
- Кастомный `AudioProcessor` в ExoPlayer (софт-клиппер в PCM) — максимальный контроль, но это свой плагин к `just_audio`; откладываем.
- `libebur128`/NDK — только для анализа, не для реального времени.

### Как прикрепить эффект
`just_audio` не оборачивает `DynamicsProcessing`, поэтому:
- берём **audio session id** плеера (`AudioPlayer.androidAudioSessionId`/поток);
- создаём `DynamicsProcessing(priority, sessionId, config)` и храним ссылку;
- при смене сессии (новый трек/источник) **переприкрепляем** эффект;
- при освобождении плеера — release.

Реализация — небольшой platform channel (по образцу нашего SAF-канала): `audioLimiter.enable/disable`, `setCeiling`, `setAttack/Release`, `attach(sessionId)`.

### Порядок в цепочке
`LoudnessEnhancer` (усиление) → **лимитер**. В Android порядок эффектов на одной сессии задаётся приоритетом (`AudioEffect.setPriority`), поэтому лимитеру задаём более высокий приоритет, чтобы он обрабатывал сигнал после boost.

### Настройки по умолчанию
- Потолок: **−1 дБFS**.
- Атака: 5–10 мс (быстро ловим пики), восстановление: 100–300 мс.
- Ratio/порог подбираем так, чтобы на типичной книге «pumping» был неслышим; при сомнениях — ratio ближе к лимитеру (высокий), а не компрессору.

### Абстракция и деградация
- В domain: `AudioLimiter` (интерфейс: enable/disable, setCeiling, применять к сессии) + модель настроек.
- Android-реализация поверх platform channel; на неподдерживаемых API (< 28) и других платформах — no-op реализация (функция недоступна, UI показывает это).
- Настройка включается в общий экран настроек воспроизведения (рядом с громкостью/boost).

### Хранение
Настройки лимитера — в SharedPreferences (глобально), аналогично `volume-controls`.

## Risks
- «Pumping»/артефакты при неверных настройках — подбираем мягкие значения, даём выключение.
- Android < 28: `DynamicsProcessing` недоступен — no-op.
- Приоритеты эффектов могут отличаться на разных устройствах/производителях — проверяем порядок и при необходимости компенсируем.
- Лимитер не спасёт от клиппинга, уже «зашитого» в сам файл, — это ограничение источника, а не обработки.
- iOS: нужен отдельный путь (`AVAudioUnitDynamicsProcessor`), вне этого change.
